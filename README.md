# MouseScrollFix

Menu bar utility for macOS: **Natural scrolling stays on for the trackpad, the mouse scrolls classically** — simultaneously, without touching the system-wide Natural scrolling setting.

Your mouse is whatever macOS sees as a pointing device: USB, 2.4 GHz receiver, Bluetooth, high-resolution or free-spinning wheels, Magic Mouse, Razer, Logitech — no per-model support list to maintain.

The interface follows your macOS language (English or Russian) and can be switched manually in Settings.
**Русская документация: [README.ru.md](README.ru.md).**

---

## 1. What it actually does

macOS has **one** Natural scrolling preference (`com.apple.swipescrolldirection`) shared by mouse and trackpad, and **no public API identifies which device produced a scroll event**. So the app does not try to identify devices. It classifies each scroll *stream* from documented Quartz fields and applies the direction that matches the class:

| Stream evidence | Class | Natural ON (default) | Natural OFF |
|---|---|---|---|
| `mayBegin`, or an established gesture | trackpad | leave alone | invert (restore natural) |
| phased, but no `mayBegin` (Magic Mouse) | touch surface | leave alone | invert |
| line-based deltas, no phases | wheel mouse | **invert** | leave alone |
| pixel-based, no phases, no active gesture | pixel mouse | **invert** (when a mouse is present) | leave alone |
| posted by another process | injected | **invert** (configurable) | leave alone |

Three guards keep the trackpad safe under this "everything that is not a gesture is a mouse" policy:

1. **Sticky gesture window** — from `mayBegin`/`began` to `ended`/`cancelled`, plus the momentum tail, every event belongs to the trackpad regardless of its flags.
2. **Grace gap (400 ms)** — phase-free pixel events just after a gesture still belong to the trackpad.
3. **Inventory fast path** — with no external pointing device present, ambiguous pixel input is left untouched.

Verified on the development machine: the built-in trackpad advertises `Digitizer/Touch Pad (0x0D/0x05)` *and* `Generic Desktop/Mouse (0x01/0x02)` on one device, with `PrimaryUsage = Mouse`. That is why classification uses the usage *pairs*, never the primary usage.

## 3. Build and run

```sh
cd MouseScrollFix

# 1. Tests (no framework needed, runs anywhere)
./scripts/run-tests.sh

# 2. App icon (only to regenerate Resources/AppIcon.icns)
swift scripts/make-icon.swift

# 3. Build the app bundle
./scripts/build-app.sh              # release + ad-hoc signature

# 4. Disk image for distribution
./scripts/make-dmg.sh               # build/MouseScrollFix-<version>.dmg

# 5. Install somewhere stable, then launch
cp -R build/MouseScrollFix.app /Applications/
open /Applications/MouseScrollFix.app
```

`make-dmg.sh` produces a compressed image whose Finder window is laid out for
drag-and-drop install: the app on the left, an **Applications** shortcut on the right,
the read-me underneath, icon view, and a fixed window size. The layout is written
straight into `.DS_Store` by `scripts/dmg-layout.py` (standard `Bud1`/B-tree format,
Python standard library only), so **no permission to control Finder is required** —
the usual AppleScript approach fails in sandboxed or headless builds.

The image is created with `hdiutil`, which the DiskImages framework behind it refuses
to run inside a restricted sandbox — run that one script from a normal Terminal window.

### Background picture for the DMG window

`make-dmg.sh` gives the window a plain light background, an icon layout and a fixed
size. A real *picture* (the arrow and captions, generated by
`scripts/make-dmg-background.swift`) needs one manual step, because Finder only accepts a
background image through an alias record and the Carbon Alias Manager that produced those
has been removed from recent macOS:

```sh
./scripts/dmg-add-background.sh
```

That script builds a writable image, mounts it, writes the icon layout, opens the volume
in Finder and stops with instructions: press ⌘J, choose **Background → Picture**, drag
`Resources/dmg-background.png` onto the preview well, close the window, press Return. It
then ejects, compresses to a read-only image and verifies it.

The alternative — driving Finder from a script — requires granting that script
permission to control Finder; this project deliberately avoids asking for it.

Then:

1. On first launch a window explains the single permission the app needs, in the
   language of your system.
2. Click **Open System Settings** and enable *MouseScrollFix* in
   **System Settings → Privacy & Security → Accessibility**. On recent releases that
   pane may be labelled **Device Control and Data Access**.
3. Back in the window, click **Check again** — it switches to "Permission granted".
4. Scroll once with the mouse and once on the trackpad. The menu shows
   `Mouse scrolling: ON` and the detected devices.

The same window is always one click away in the menu: **Permissions…**.

> Keep the app at a stable path. Rebuilding changes the ad-hoc signing identity, so macOS may ask for Accessibility again after every rebuild — that is expected, not a bug.

## 4. Settings

| Setting | Default | Notes |
|---|---|---|
| Invert mouse scrolling | ON | master switch |
| Invert vertical scrolling | ON | axis 1 |
| Invert horizontal scrolling | OFF | axis 2 |
| Automatic mouse detection | ON | use the device inventory for the fast path |
| High-resolution wheel input | Treat as mouse (invert) | switch to *Pass through* for the conservative behaviour |
| Touch surface without `mayBegin` | Keep natural | Magic Mouse behaves like a trackpad; can be inverted |
| Events posted by other apps | Treat as mouse | vendor drivers, remote desktop |
| Language | System | English or Russian; follows the macOS language by default |
| Launch at Login | OFF | `SMAppService` |
| Show menu bar icon | ON | turn off to hide the icon; reopen via `MouseScrollFix` in the menu bar after re-enabling |
| Record scroll decisions | OFF | in-memory trace, exportable as JSON Lines |

Settings live in the app's own `UserDefaults` domain. The app reads `com.apple.swipescrolldirection` and **never writes it**, nor any other system domain.

## 5. Manual test checklist

```
[ ] Built-in trackpad scrolls naturally (two fingers, both directions)
[ ] Trackpad momentum/inertia keeps the natural direction
[ ] Razer Orochi V2 (USB / 2.4 GHz receiver) is inverted
[ ] Razer Orochi V2 in Bluetooth mode is inverted
[ ] Trackpad stays natural WHILE the mouse is connected
[ ] Alternating trackpad gesture and wheel in the same app does not stick or flip
[ ] Fast alternation (stress) never inverts the trackpad
[ ] Horizontal scrolling honours the horizontal toggle
[ ] Notched wheel feels correct; free-spin/high-resolution wheel per your policy
[ ] Pause with fingers resting on the trackpad, then continue — same direction
[ ] Unplug the mouse: trackpad still natural (pixel input passes through)
[ ] Replug the mouse: wheel is inverted again
[ ] Sleep and wake: filter recovers (check "Tap recreated" in Diagnostics)
[ ] Revoke Accessibility while running: input does NOT hang, app reports "Permission required"
[ ] Restart the app: settings persist, filter returns
[ ] Natural scrolling = OFF in System Settings: trackpad becomes classic, mouse untouched
[ ] Launch at Login registers (app must be signed and in a stable path)
[ ] Quit from the menu leaves no background process
```

## 6. Troubleshooting

### The event tap does not start

Check `--dump-status` → `accessibilityTrusted` and `hasActiveScrollTap(ours)`.

- `accessibilityTrusted: false` → grant it (step 3 above), then use **Retry filter** in the menu.
- Trusted, but `hasActiveScrollTap(ours): false` → another process may be interfering; run **Diagnostics → Reinstall filter**.
- The app never blocks input when it cannot create a tap; it reports "Permission required" and passes everything through untouched.

### Accessibility permission does not stick

Rebuilding an ad-hoc signed app changes its identity. Remove the stale entry in System Settings, add the current `MouseScrollFix.app`, and grant again. To clear everything and start over:

```sh
tccutil reset Accessibility com.mousescrollfix.MouseScrollFix
```

Keep the app in `/Applications` and avoid rebuilding once you are happy with it.

### The mouse scrolling is not inverted

1. **Diagnostics** → is the mouse listed under *Devices* with kind `mouse`? If it is not listed at all, the device is not exposing a mouse/pointer usage pair — `--dump-devices` shows the raw usages.
2. Look at the counters: if `Inverted` stays at 0 while you scroll, classification is sending the stream to another class. Turn on **Record scroll decisions**, scroll, save the trace and look at `class`/`reason`.
3. Common cause: your mouse's driver emits pixel deltas with no phases while no external pointer is detected → the fast path protects the trackpad. Check `hasExternalPointer` in `--dump-status`.
4. Another tool (Scroll Reverser, LinearMouse, Mos, Karabiner) may be filtering the same events. Quit the others and retry.

### The trackpad also becomes inverted (critical)

This is the failure mode that matters most. Please capture a trace:

1. Enable **Record scroll decisions**.
2. Perform the trackpad gesture that misbehaves.
3. Save the trace and inspect the `reason` for the offending records.

Reasons that indicate a real classification problem: `phaseFreePixel` or `discreteLineTick` while you were scrolling the trackpad, `momentumWithoutOwner`, or `graceContinuation` expiring mid-gesture. As an immediate workaround set **High-resolution wheel input → Pass through**.

### Momentum is wrong

A momentum tail belongs to the gesture that produced it. If it flips mid-tail, the trace will show `momentum` records changing `class`. Check whether another utility posts synthetic scroll events at the same time — that is what the `injected` policy is for.

### A Bluetooth mouse behaves differently

Bluetooth Low Energy devices report the transport string `"Bluetooth Low Energy"` (with spaces), while the SDK constant is `"BluetoothLowEnergy"`; both are handled. BLE mice also connect/disconnect more often, so watch the *Devices* list and the *Tap recreated* counter.

### Magic Mouse behaves differently

Magic Mouse is a touch surface: it emits scroll phases but, as Apple documents, never `mayBegin`. It is therefore classified as `touchSurfaceOther` and keeps natural scrolling by default. To invert it, switch **Touch surface without mayBegin → Invert as mouse**. It has no notched wheel, so natural is usually what you want.

### The app stops receiving events

macOS disables taps on slow callbacks, on heavy input, after sleep, and after a low-battery standby. The app re-enables in place, recreates the tap if that fails, and runs a 5-second health check. If the momentum of this is visible in **Tap recreated** climbing, please capture a trace and a Diagnostics screenshot — that is a real bug in the app, not expected behaviour.

## 7. Project layout

```
MouseScrollFix/
├── Package.swift
├── Sources/
│   ├── MouseScrollFixCore/           # pure logic, no system frameworks, fully unit tested
│   │   ├── Models/                   # StreamClass, ScrollAction, ScrollFields, ClassifierState,
│   │   │                             # SettingsSnapshot, PointerDevice, PhaseConstants
│   │   ├── Classification/           # ScrollStreamClassifier, ScrollPolicyEngine, ScrollDecisionPipeline
│   │   ├── Rewriting/                # ScrollMutationPlan, SyntheticEventMarker
│   │   └── Localization/             # TextKey, English + Russian tables, language resolution
│   ├── MouseScrollFixPlatform/       # CGEventTap, CGEvent access, IORegistry, permissions, settings
│   ├── MouseScrollFixUI/             # AppStatusModel, SwiftUI panes, permission window
│   ├── MouseScrollFixApp/            # @main entry, AppDelegate, menu bar, CLI diagnostics
│   └── MouseScrollFixTests/          # framework-free test suite
├── Resources/                        # Info.plist, entitlements, AppIcon.icns
└── scripts/                          # build-app.sh, make-dmg.sh, dmg-layout.py, make-icon.swift, run-tests.sh
```

Key implementation notes:

- **Tap location** `kCGSessionEventTap`, `headInsert`, active filter, mask `1 << kCGEventScrollWheel` (bit 22) — the minimum surface, no keyboard or pointer-motion subscription.
- **Threading** — the tap owns a dedicated `Thread` with its own `CFRunLoop`; all stream state lives there. Nothing blocking, no logging, no IPC in the callback.
- **Field writes** — `DeltaAxis` first, then `PointDeltaAxis`, then `FixedPtDeltaAxis`, then the newer accelerated/raw fields, each only when non-zero. Writing `DeltaAxis` makes macOS recompute the point representations (8× and 1×), so the order is what preserves smooth scrolling.
- **Recursion guard** — own synthetic events are tagged in `kCGEventSourceUserData` and never re-processed.
- **No private API.** `CGEventCopyIOHIDEvent`, `IOHIDEventGetSenderID`, `CGEventGetSendingDevice` and the undocumented `CGEventField` sender-id route are all deliberately unused.

## 8. Known limitations

These are platform limits, not bugs to be fixed later:

- **No per-event device identity.** No public API maps a scroll event to a HID device, so "invert mouse A but not mouse B" is impossible. Classification is per stream; the device list feeds policy, not routing.
- **Magic Mouse is a touch surface**, not a wheel — it keeps natural scrolling by default (configurable).
- **High-resolution / free-spinning wheels** can emit pixel deltas indistinguishable from a trackpad's. They are treated as a mouse by default; the conservative mode is one setting away.
- **Vendor drivers** (Logi Options+, Razer Synapse) may post their own events; the `injected` policy applies.
- **Remote desktop and virtual machines** can deliver scroll events with unusual metadata.
- **Conflicting utilities** that filter the same events will fight; quit them.
- **Ad-hoc signing** means permissions reset after each rebuild; distribution needs Developer ID + notarization.

## 10. Releasing

The repository ships two GitHub Actions workflows:

- `.github/workflows/ci.yml` — builds, runs the test suite, assembles the app bundle and
  the disk image, and uploads the `.dmg` as a build artifact.
- `.github/workflows/release.yml` — on a `v*` tag, does the same and attaches the `.dmg`
  to a GitHub release with generated notes.

```sh
git tag v1.0.0
git push origin v1.0.0
```

Remember to bump `CFBundleShortVersionString` in `Resources/Info.plist` and add a
`CHANGELOG.md` entry before tagging.

### Distribution notes

The bundled scripts sign ad-hoc, which is fine for local use and for people who download
and right-click → Open. For a build that opens without warnings on other machines:

```sh
MSF_HARDENED=1 codesign --force --options runtime \
    --sign "Developer ID Application: Your Name (TEAMID)" build/MouseScrollFix.app
xcrun notarytool submit build/MouseScrollFix-1.0.0.dmg --keychain-profile AC_PROFILE --wait
xcrun stapler staple build/MouseScrollFix-1.0.0.dmg
```

`SMAppService` (Launch at Login) also requires a signed app in a stable location, so login
items only work reliably with a Developer ID signature.
