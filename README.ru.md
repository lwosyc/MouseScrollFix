# MouseScrollFix

Утилита в строке меню macOS: **трекпад сохраняет Natural Scrolling, мышь прокручивает классически** — одновременно, без изменения системной настройки.

Мышь — любая, которую macOS видит как указывающее устройство: USB, приёмник 2,4 ГГц, Bluetooth, колесо высокого разрешения или free-spin, Magic Mouse, Razer, Logitech. Списка поддерживаемых моделей нет и не требуется.

Интерфейс автоматически выбирает язык по языку системы (русский или английский) и переключается вручную в настройках.

---

## 1. Установка из DMG

1. Откройте `MouseScrollFix-1.0.0.dmg`.
2. В открывшемся окне **перетащите MouseScrollFix на ярлык Applications** справа
   (окно уже свёрстано под это: приложение слева, «Applications» справа, инструкция снизу).
3. Запустите приложение из Applications. Оно появится **в строке меню**, а не в Dock.
4. При первом запуске откроется окно с объяснением, какое разрешение нужно и зачем. Нажмите **«Открыть системные настройки»**.
5. Включите переключатель напротив **MouseScrollFix** в разделе
   **«Конфиденциальность и безопасность» → «Универсальный доступ»**
   (в новых версиях macOS этот раздел может называться **«Управление устройствами и доступ к данным»**).
6. Вернитесь в окно приложения и нажмите **«Проверить снова»** — состояние сменится на «Разрешение выдано».

> Сборка подписана ad-hoc, поэтому Gatekeeper может предупредить при первом запуске. Тогда щёлкните по приложению **правой кнопкой → «Открыть»**.
>
> Держите приложение в `/Applications`. Если пересобрать неподписанную сборку, меняется её идентичность, и macOS попросит разрешение заново — это нормально, а не ошибка.

## 2. Что именно делает приложение

В macOS **одна** настройка Natural scrolling (`com.apple.swipescrolldirection`) на мышь и трекпад, и **нет публичного API**, которое сообщало бы, какое устройство породило событие прокрутки. Поэтому приложение не пытается опознать устройство. Оно определяет класс **потока событий** по документированным полям Quartz и применяет направление, соответствующее классу:

| Признаки потока | Класс | Natural включён (по умолчанию) | Natural выключен |
|---|---|---|---|
| `mayBegin` или активный жест | трекпад | не трогаем | инвертируем (возвращаем natural) |
| есть фазы, но нет `mayBegin` (Magic Mouse) | сенсорная поверхность | не трогаем | инвертируем |
| строчные дельты без фаз | мышь с колесом | **инвертируем** | не трогаем |
| пиксельные дельты без фаз и без жеста | мышь высокого разрешения | **инвертируем** (если мышь подключена) | не трогаем |
| событие от другого процесса | внедрённое | **инвертируем** (настраивается) | не трогаем |

Трекпад защищают три независимых механизма:

1. **Окно жеста** — от `mayBegin`/`began` до `ended`/`cancelled` плюс инерция: все события принадлежат трекпаду независимо от их флагов.
2. **Пауза 400 мс** после жеста — пиксельные события без фаз в этот момент тоже считаются трекпадом.
3. **Быстрый путь по инвентарю** — если внешних указывающих устройств нет, неоднозначный пиксельный ввод не трогается вовсе.

Проверено на реальной машине: встроенный трекпад сообщает **одновременно** `Digitizer/Touch Pad (0D/05)` и `Generic Desktop/Mouse (01/02)`, причём его primary usage — Mouse. Именно поэтому классификация идёт по списку usage-пар, а не по primary usage.

## 4. Сборка из исходников

```sh
cd MouseScrollFix

./scripts/run-tests.sh          # тесты (56 тестов, 631 проверка)

swift scripts/make-icon.swift   # перегенерировать иконку (Resources/AppIcon.icns)

./scripts/build-app.sh          # собрать build/MouseScrollFix.app (ad-hoc подпись)

./scripts/make-dmg.sh           # собрать build/MouseScrollFix-1.0.0.dmg
```

Окно DMG свёрстано под установку перетаскиванием: приложение слева, ярлык
**Applications** справа, инструкция снизу, режим иконок и фиксированный размер окна.
Раскладка пишется напрямую в `.DS_Store` скриптом `scripts/dmg-layout.py` (формат
`Bud1`/B-tree, только стандартная библиотека Python), поэтому **разрешение на
управление Finder не требуется** — обычный подход через AppleScript в песочнице и при
агентной сборке не работает.

### Фоновая картинка для окна DMG

По умолчанию фон — ровный светлый. Настоящая картинка со стрелкой и подписями
(её рисует `scripts/make-dmg-background.swift`) требует одного ручного шага: Finder
принимает фон-картинку только через alias-запись, а Carbon Alias Manager, который такие
записи создавал, из свежих macOS удалён.

```sh
./scripts/dmg-add-background.sh
```

Скрипт собирает записываемый образ, монтирует его, записывает раскладку иконок,
открывает том в Finder и останавливается с инструкцией: нажмите ⌘J, выберите
**«Фон» → «Картинка»**, перетащите `Resources/dmg-background.png` в окошко предпросмотра,
закройте окно и нажмите Return в терминале. Дальше он сам отключит том, сожмёт образ до
read-only и проверит контрольную сумму.

Альтернатива — управлять Finder из скрипта — потребовала бы выдать скрипту разрешение на
управление Finder; проект намеренно этого не просит.

Если сборка идёт внутри ограниченной песочницы (агент, контейнер) и компилятор не может писать в кэш модулей:

```sh
swift build --disable-sandbox
```

Скрипты уже передают этот флаг и перенаправляют кэши в `.modulecache/` и `.tmp/`.

Создание DMG требует `hdiutil`, который обращается к DiskImages и в ограниченной песочнице блокируется — запускайте `make-dmg.sh` в обычном окне Терминала.

### Диагностика из терминала

## 6. Окно разрешений при первом запуске

При первом запуске открывается окно, в котором по-русски объяснено:

- какое разрешение нужно — **Accessibility**;
- зачем именно: менять направление прокрутки до того, как macOS отдаст события приложениям;
- чего приложение **не** делает: не читает текст, не следит за клавиатурой, не захватывает экран, не имеет кода для работы с сетью, не меняет системную настройку прокрутки;
- пошаговая инструкция с текущим названием раздела в системных настройках;
- кнопки **«Открыть системные настройки»**, **«Проверить снова»** и **«Позже»**.

Окно можно открыть в любой момент из меню: **«Разрешения…»**. Как только разрешение выдано, оно показывает «Разрешение выдано» и кнопку «Готово».

## 7. Чек-лист ручной проверки

```
[ ] Встроенный трекпад прокручивает natural (двумя пальцами, в обе стороны)
[ ] Инерция трекпада сохраняет natural
[ ] Razer Orochi V2 (USB / приёмник 2,4 ГГц) инвертируется
[ ] Razer Orochi V2 в режиме Bluetooth инвертируется
[ ] Трекпад остаётся natural, ПОКА подключена мышь
[ ] Чередование жеста на трекпаде и колеса в одном приложении не «залипает»
[ ] Быстрое чередование (стресс) не инвертирует трекпад
[ ] Горизонтальная прокрутка подчиняется своему переключателю
[ ] Колесо высокого разрешения / free-spin — по выбранной политике
[ ] Пауза с пальцами на трекпаде, затем продолжение жеста — то же направление
[ ] Отключение мыши: трекпад остаётся natural
[ ] Повторное подключение мыши: колесо снова инвертируется
[ ] Сон/пробуждение: фильтр восстанавливается («Tap пересоздан» в диагностике)
[ ] Отзыв Accessibility на работающем приложении: ввод НЕ зависает
[ ] Перезапуск приложения: настройки сохраняются, фильтр возвращается
[ ] Natural scrolling = выключено в системе: трекпад становится классическим, мышь не трогается
[ ] Автозапуск при входе регистрируется (приложение подписано и лежит в постоянном месте)
[ ] «Завершить» в меню не оставляет процессов
```

## 8. Если что-то работает не так

**Фильтр не запускается.** `--dump-status` покажет `accessibilityTrusted` и `hasActiveScrollTap(ours)`.
Если разрешение выдано, но tap не активен — «Диагностика» → **«Переустановить фильтр»**. Приложение никогда не блокирует ввод, если tap создать не удалось: оно сообщает «Нужно разрешение» и пропускает все события без изменений.

**Разрешение не держится.** Пересборка ad-hoc сборки меняет идентичность. Удалите старую запись в системных настройках, добавьте текущее приложение и выдайте доступ снова. Полный сброс:

```sh
tccutil reset Accessibility com.mousescrollfix.MouseScrollFix
```

**Мышь не инвертируется.** Проверьте по порядку:
1. «Устройства» — мышь есть в списке с классом «мышь»? Если её нет вовсе, устройство не сообщает usage-пару мыши; `--dump-devices` покажет сырые usages.
2. Счётчики: если «Инвертировано» остаётся 0, поток отнесён к другому классу. Включите **«Записывать решения по потокам»**, прокрутите, сохраните трассировку и посмотрите `class`/`reason`.
3. Частая причина: драйвер мыши отдаёт пиксельные дельты без фаз, а внешнее указывающее устройство не обнаружено — срабатывает быстрый путь защиты трекпада. Проверьте `hasExternalPointer` в `--dump-status`.
4. Другая утилита (Scroll Reverser, LinearMouse, Mos, Karabiner) фильтрует те же события. Закройте остальные и повторите.

**Трекпад тоже инвертируется (критично).** Включите запись трассировки, повторите проблемный жест, сохраните файл и посмотрите поле `reason`. Признаки реальной ошибки классификации: `phaseFreePixel` или `discreteLineTick` во время жеста на трекпаде, `momentumWithoutOwner`, либо `graceContinuation`, истекающий посреди жеста. Временное решение — **«Колесо высокого разрешения» → «Пропускать без изменений»**.

**Инерция идёт не туда.** Хвост инерции принадлежит породившему его жесту. Если направление меняется посреди хвоста, в трассировке будет видно смену `class` в записях `momentum`. Часто причина — другая утилита, которая постит свои события; для этого есть политика «События от других приложений».

**Bluetooth-мышь ведёт себя иначе.** Устройства Bluetooth Low Energy сообщают транспорт `"Bluetooth Low Energy"` (с пробелами), тогда как константа в SDK — `"BluetoothLowEnergy"`; поддержаны оба варианта. BLE-мыши чаще переподключаются — следите за списком устройств и счётчиком «Tap пересоздан».

**Magic Mouse ведёт себя иначе.** Это сенсорная поверхность: она отдаёт фазы, но, как документирует Apple, никогда не выдаёт `mayBegin`. Поэтому она классифицируется как сенсорная поверхность и по умолчанию сохраняет natural. Чтобы инвертировать — **«Сенсорная поверхность без mayBegin» → «Инвертировать как мышь»**. Нотированного колеса у неё нет, так что natural обычно и нужен.

**Приложение перестало получать события.** macOS отключает tap при медленном обработчике, при тяжёлом вводе, после сна и после низкого заряда. Приложение включает tap обратно, пересоздаёт его при неудаче и раз в 5 секунд проверяет здоровье. Если счётчик «Tap пересоздан» растёт — это реальная проблема, пришлите трассировку и снимок вкладки «Диагностика».

## 9. Структура проекта

```
MouseScrollFix/
├── Package.swift
├── Sources/
│   ├── MouseScrollFixCore/        # чистая логика: модели, классификатор, политика, план мутаций, локализация
│   ├── MouseScrollFixPlatform/    # CGEventTap, доступ к полям CGEvent, IORegistry, разрешения, настройки
│   ├── MouseScrollFixUI/          # AppStatusModel, окна SwiftUI (настройки, устройства, диагностика, разрешения)
│   ├── MouseScrollFixApp/         # @main, AppDelegate, меню в строке меню, CLI-диагностика
│   └── MouseScrollFixTests/       # тесты без внешнего фреймворка
├── Resources/                     # Info.plist, entitlements, AppIcon.icns
└── scripts/                       # build-app.sh, make-dmg.sh, dmg-layout.py, make-icon.swift, run-tests.sh
```

Принципиальные решения:

- **Расположение tap:** `kCGSessionEventTap`, `headInsert`, активный фильтр, маска ровно `1 << kCGEventScrollWheel` (бит 22) — минимальная поверхность, никакой подписки на клавиатуру и движение указателя.
- **Потоки:** у tap собственный `Thread` со своим `CFRunLoop`; всё состояние потока живёт там. В обработчике нет блокировок, логирования и IPC.
- **Порядок записи полей:** сначала `DeltaAxis`, затем `PointDeltaAxis`, затем `FixedPtDeltaAxis`, затем новые accelerated/raw — и каждое только если значение ненулевое. Запись `DeltaAxis` заставляет macOS пересчитать точечные представления (×8 и ×1), поэтому порядок и сохраняет плавную прокрутку.
- **Защита от рекурсии:** собственные синтетические события помечаются в `kCGEventSourceUserData` и никогда не обрабатываются повторно.
- **Приватные API не используются.** `CGEventCopyIOHIDEvent`, `IOHIDEventGetSenderID`, `CGEventGetSendingDevice` и недокументированный путь через `CGEventField` сознательно не задействованы.

## 10. Известные ограничения

Это ограничения платформы, а не недоделки:

- **Нет определения устройства по событию.** Публичного API, связывающего событие прокрутки с HID-устройством, не существует, поэтому «инвертировать мышь A, но не мышь B» невозможно. Классификация — по потоку; список устройств влияет на политику, а не на маршрутизацию.
- **Magic Mouse — сенсорная поверхность**, а не колесо; по умолчанию сохраняет natural (настраивается).
- **Колёса высокого разрешения и free-spin** могут отдавать пиксельные дельты, неотличимые от трекпада. По умолчанию считаются мышью; консервативный режим — одна настройка.
- **Драйверы производителей** (Logi Options+, Razer Synapse) могут постить свои события — работает политика «События от других приложений».
- **Удалённый рабочий стол и виртуальные машины** могут доставлять события с необычными метаданными.
- **Конфликтующие утилиты** будут мешать друг другу; закройте их.
- **Ad-hoc подпись** означает сброс разрешений после пересборки; для распространения нужны Developer ID и нотаризация.

### О подписи

Скрипты подписывают ad-hoc — этого достаточно для локального использования и для тех,
кто скачает образ и откроет приложение через «правой кнопкой → Открыть». Чтобы сборка
открывалась без предупреждений на чужих машинах, нужен Developer ID и нотаризация:

```sh
MSF_HARDENED=1 codesign --force --options runtime \
    --sign "Developer ID Application: Ваше Имя (TEAMID)" build/MouseScrollFix.app
xcrun notarytool submit build/MouseScrollFix-1.0.0.dmg --keychain-profile AC_PROFILE --wait
xcrun stapler staple build/MouseScrollFix-1.0.0.dmg
```

`SMAppService` (автозапуск при входе) тоже требует подписанного приложения в постоянном
месте, так что надёжно автозапуск работает только с Developer ID.
